## What you are looking at

Identity Before Detection is a hands-on project: building the IT and security environment for Via Wash, a laundry pickup and delivery business in development, inside a Microsoft test environment. The aim is to understand why each decision is made, not just which buttons to press.

## How it is organised

The project is split into **topics**. Each topic has an overview page explaining what it is about and why it comes at that point, and under it are the individual pages.

1. **Start here.** The business, the plan and the people.
2. **Preparing the Microsoft environment.** Getting the tenant and licence, then checking each service is actually ready. The E5 licence and the Intune groundwork are documented so far.
3. **Designing identity and access.** Deciding who should have access to what, before building anything.
4. **Identity lifecycle.** Joiners, movers and leavers: how access changes as people do.
5. **Application security.** The Via Wash customer app, and the security work already built into it.

Everything else, from Entra ID and devices to on-premises IT, monitoring, incident response and IT Support & Operations, is on the [roadmap]({{ '/identity-before-detection/' | relative_url }}#roadmap). Those areas get their own pages only once I have actually done the work.

## Using it as a study guide

If you are building something similar, follow the topics in order. Every step page answers the same four questions: what the step is, why it matters, what is done, and how to check it worked. Microsoft moves menus around often, so the pages focus on the outcome you need rather than an exact sequence of clicks.

## Reading the progress

Every page says plainly where it stands. **Written** means the work is done and backed by evidence. **Under way** means it has started but isn’t finished. **Not started** marks the design and lifecycle pages, which set out the thinking before any of it is built. Pages describing practical work only appear once that work has actually happened.
